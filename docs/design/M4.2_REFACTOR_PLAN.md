# M4.2 — Product Workflow Refactor: PLAN

> Companion to `M4.2_GAP_ANALYSIS.md`. Executed **milestone by milestone**, each a logical
> commit that leaves the tree green (Project Rules §3–4). Pricing, bidding, and negotiation are
> **deferred** (architecture must allow them later, but no engine now). No Clean-Architecture
> violations: new services get interfaces, business logic stays out of controllers, repository
> pattern and application-service (CQRS-style) conventions preserved.

## Sequencing rationale

Roles are the keystone — everything gates on them, so **Milestone A comes first**. Geo (C) must
precede matching (D) because matching filters on distance/corridor. Clients (G) come after the
backend seams exist so they bind to real contracts, not stubs.

## Per-milestone detail

### A — Role-based registration (keystone)
- Extend `RegisterRequest` with `AccountType` (`Driver` | `LoadOwner`), validated (FluentValidation);
  reject any other value. Map `LoadOwner→Roles.Shipper`.
- `AuthService.RegisterAsync` assigns the role via `UserManager.AddToRoleAsync` inside the create flow;
  role goes into the JWT (already wired via `GetRolesAsync`).
- Add a `roles` claim reader to both clients (G).
- **Security:** whitelist to {Driver, Shipper}; never honor internal/admin from the client (S5).
- **Tests:** register-as-driver grants Driver; register-as-loadowner grants Shipper; unknown/blank/admin
  type rejected; token carries the role. Keep the 147 green.

### B — Onboarding + self-serve documents
- Driver onboarding resolves `UserProfile`/`DriverProfile` from the **JWT user id** (already does for
  register). Add `GET drivers/me` returning the caller's driver profile id.
- Documents upload: server resolves the owner driver from the JWT (kill the W5 "first driver" hack);
  `POST documents/upload` no longer trusts a client `ownerId` for driver docs.
- "Vehicle owner? YES" → create `Carrier` + `Association(Driver)` for the owner-operator; vehicle
  registration becomes driver-reachable.
- **Tests:** `drivers/me`; upload binds to the caller; owner-operator carrier creation.

### C — Location intelligence
- `ILocationSearchService.SearchAsync(query)` → candidate places (name, lat/lng, district, state, pin).
- `IRouteService.RouteAsync(origin, dest)` → `{ distanceKm, estimatedDuration }`.
- Infra impls: **Nominatim** (search) + **OSRM** (route) via `HttpClient` (dev, no key), behind the
  interface so a **Google Places/Routes** adapter drops in later (user mandate). Config-driven base URLs
  + user-agent + timeout; **fail-soft** (a route failure doesn't block posting — store coords, mark
  distance unknown, never fabricate).
- Extend `Location` VO with optional `District`/`State`/`Pin`; add `DistanceKm` + `EstimatedDuration`
  to `Load` (+ EF mapping + migration).
- **Tests:** service adapters against a fake `HttpMessageHandler`; Location VO; Load persists distance.

### D — Matching engine v1
- `IMatchingService.FindCompatibleLoadsForDriver(driverId)` applying MVP filters **1,2,6,7,8** now
  (type, capacity, driver Available, driver verified, vehicle verified) — the ones our data supports —
  and **3,4,5** (geo corridor/time) as config-tunable, best-effort until PostGIS lands. Zero matches is
  a first-class result.
- `loads/available` → returns only compatible loads for the calling driver. Highest test coverage
  (Project Rules §4): explicit pass/fail per filter + "no candidate" path.

### E — Load creation + gated accept
- `PostLoadRequest` takes **place selections** (from C's search) not raw coords; server geocodes/routes
  and stores distance/ETA. No `Distance`/`ETA` field asked of the user.
- `AcceptAsync(loadId, driverId-from-JWT)` enforces: driver verified + vehicle verified + compatible
  (reuse D) before `Matched→Booked`; creates the Trip assignment.

### F — Lists + lifecycle
- `GET loads/mine` (shipper), `GET trips/mine` (driver), `GET trips` (ops, paged). Trip transitions
  validated against current state.

### G1/G2 — Clients (bind to the above)
- Admin: decode JWT role, gate nav, add verification queues (drivers/vehicles/load-owners/docs) with
  real reject reasons; fix the envelope unwrap.
- Mobile: **Choose Account Type** → role-specific registration; read role from JWT; **remove Post-Load
  from the driver app**; location autocomplete on load creation (load-owner build); map driven by real
  coordinates; kill dead `/dashboard` nav and fake status chips.

### H — Documentation
- ADR-0017 (this refactor's decisions + the §11 resolved ambiguities); update `04_CURRENT_TASK.md`,
  `05_NEXT_TASKS.md`, Technical Bible §12/§13 notes, and READMEs. Full `dotnet test` + `ng build` +
  `flutter build` sweep.

## Non-goals (explicitly deferred)
Pricing engine, bidding, negotiation, escrow/collected payments, PostGIS geometry migration, ML
ranking, push/SMS/WhatsApp delivery, separate Fleet/Dispatcher console. Architecture leaves seams for
each.
